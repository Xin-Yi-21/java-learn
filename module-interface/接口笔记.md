# 接口学习案例

每个包都有独立的 `Test.java`，运行它观察输出。接口和实现类分别放在同名文件中。
所有可运行代码适用于 Java 8，输出使用直接的类型和方法描述。

| 包 | 知识点 |
| --- | --- |
| interface_a | 接口组成、常量、抽象实例方法、默认实例方法、静态方法、成员类型 |
| interface_b | 接口多继承、类多实现、同时继承与实现；相同抽象要求实现一次、默认方法冲突重写决定 |

## 接口规则

- 接口定义要求，实现类提供具体实现；不能直接 new 接口。
- 接口没有构造方法、实例字段，也没有类的实例初始化块或静态初始化块。
- 接口字段隐含 `public static final`，必须初始化。final 限制再次赋值，不代表引用对象内部永远不可修改。
- 无方法体的接口方法隐含 `public abstract`；具体实现类必须实现所有尚未实现的抽象方法，否则也必须是抽象类。
- 抽象方法不能与 private、static、final 一起使用。
- default 方法隐含 public，有方法体，可以直接使用，也可以重写。default 在这里不是默认访问权限。
- 接口静态方法有方法体；Java 8 中为 public，不会被实现类或子接口继承，也不能被重写。
- 顶层接口不写 public 时是包级可见；接口本身的访问权限和接口内部成员的权限要分开判断。
- 接口中的成员类和成员接口隐含 public static，这属于嵌套类型，后续可单独学习。
- Java 9 起接口可以有 private 实例方法和 private static 方法，供接口内部复用；它们必须有方法体，不能被实现类继承或重写。本项目使用 Java 8，不在可运行案例中使用。

## 继承及方法冲突的边界

- 同名同参的抽象方法可以实现一次，前提是返回类型兼容；实现也必须满足各接口的访问权限及受检异常要求。
- 两个无继承关系的接口提供同签名默认方法时，实现类通常需要重写来解决冲突；案例 b 展示没有父类实现的直接冲突，以及子接口解决父接口默认方法冲突。
- 如果父类提供了 public 具体实例方法，能满足接口要求，优先使用父类方法。
- 如果父类声明了同签名抽象实例方法，不能仅靠接口默认方法补全，具体子类仍需实现。
- 如果子接口重写了父接口的默认方法，优先使用更具体的子接口实现。
- 一个接口的抽象方法与另一个无继承关系接口的同签名默认方法相遇，也不能简单认为默认方法自动满足要求，需要显式解决。
- 接口引用可以指向实现类对象；编译时根据引用类型检查可调用方法，运行时重写的实例方法根据实际对象执行。

## 原有学习笔记（保留原文）

```java
// 接口字段，public static final 隐式，常量化不能二次赋值。
// 接口抽象方法，public abstract隐式，由实现类实现。
// 接口默认方法，可多个，实现类重写。
// 接口静态方法，接口名调用。

// 接口与类
// 1、接口多继承。 public interface InterfaceA extends InterfaceB,InterfaceC{}
// 2、实现类多实现接口。public class InterfaceImpl implements InterfaceA,InterfaceB{}
// 3、实现类可同时继承和实现。public class Zi extends Fu implements InterfaceA,InterfaceB{}
// 4、接口抽象方法“相同的要求，实现一次”；接口默认方法是“不同的现成实现，冲突时必须自己决定”。
```

补充：默认方法实现类可以直接使用，不是必须重写；只有需要改变行为或解决冲突时才重写。
